# Central 1.1.0 (instalação simples e repositório público) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (execução nativa). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Instalar e atualizar a Central com um comando, e abrir o repositório com licença.

## Global Constraints
- **Instalação por usuário:**
  - Windows: `%LOCALAPPDATA%\Programs\central`, com o PATH em `HKCU\Environment`.
  - Unix: `~/.local/bin`, sem editar arquivos do shell; o comando só avisa quando a pasta falta no PATH.
  - Nada exige administrador.
- **Dados:** nunca são apagados por `desinstalar`.
- **Só a versão mais nova substitui o daemon:** uma CLI mais antiga não derruba um daemon mais novo.
- **Contratos:** `/v1` só ganha rotas (aditivo); o golden é regravado.

## Tasks

### Task 1: licença
- `LICENSE` MIT (João Vitor, 2026) e a seção "Licença" no README.

### Task 2: parar e trocar o daemon
- `POST /v1/daemon/encerrar` responde `{"ok":true}` e encerra o daemon com o mesmo desligamento do sinal.
- `central parar` chama essa rota e espera a porta ficar livre (até 10 s).
- `ensureDaemon`:
  - se o daemon rodando é de uma versão semver **mais antiga** que a CLI, pede para encerrar e sobe o novo;
  - o daemon 1.0.0 não tem a rota: a CLI encerra o processo pelo pid que o próprio daemon informou na `/v1/saude` (o mesmo de `daemon.json`).
- [ ] Testes: `TestEncerrarPelaAPI` (daemon), `TestCompararVersoes`, `TestCLINovaTrocaDaemonAntigo` e `TestCLIAntigaNaoDerrubaDaemonNovo` (e2e com binários compilados com `-X`), e `TestParar`.

### Task 3: `central instalar` / `central desinstalar`
- `instalar [--sem-plugin sim]`:
  - para o daemon;
  - copia o próprio executável para a pasta de instalação (sem fazer nada se ele já roda de lá);
  - acrescenta a pasta ao PATH do usuário (sem duplicar);
  - com o `claude` no PATH, roda `claude plugin marketplace add JoaoVitorSantDrade/central` e `claude plugin install central@central` (uma falha só vira aviso);
  - devolve os passos feitos.
- `desinstalar [--sem-plugin sim]`: para o daemon, tira a pasta do PATH, remove o binário (o que está rodando é removido logo depois que o processo sai) e mantém os dados, informando onde ficam.
- A lógica do PATH (acrescentar, remover, comparar sem caixa no Windows) é pura e testada. A escrita no registro fica atrás de uma interface, que os testes trocam por um arquivo (`CENTRAL_TESTE_PATH`). A pasta de destino pode ser sobrescrita por `CENTRAL_INSTALAR_EM`.
- [ ] Testes: `TestPathAcrescentaUmaVez`, `TestPathRemove` e o e2e `TestInstalarEDesinstalar`.

### Task 4: `central atualizar`
- Lê a última release da API do GitHub (`CENTRAL_RELEASES` sobrescreve a base), escolhe o binário da plataforma, baixa, confere o `SHA256SUMS` e se substitui: renomeia o executável atual para `.antigo` e grava o novo no mesmo caminho. Depois para o daemon, para o novo subir no próximo comando.
- Já na última versão, nada muda. `--versao X.Y.Z` escolhe uma versão.
- O `.antigo` de uma atualização anterior é apagado no começo da seguinte.
- [ ] Testes: `TestAtualizarDeUmaReleaseFalsa` (`httptest`) e `TestAtualizarRecusaSomaErrada`.

### Task 5: instaladores de uma linha e documentação
- `scripts/install.ps1`: baixa o binário da última release para o temporário e roda `instalar`.
- `scripts/install.sh`: o mesmo para Linux e macOS.
- Os dois entram como assets da release (`scripts/release.ps1` os copia para `dist/`).
- README "Instalar" vira a uma linha mais as alternativas. CHANGELOG da 1.1.0.
